# Operating Pokaimon's autonomous model-evolution pipeline

**Status:** The pipeline is implemented on the feature branch. Production automatic publishing remains disabled until the one-time repository setup and approval. The synthetic integration test proves the pipeline without claiming fictional models exist.

## Automatic release flow

Daily GitHub Actions discovery calls the OpenAI, Anthropic and xAI official model-list APIs without inference. New IDs require an official API listing AND a matching provider-owned documentation page. Initial scans bootstrap the inventory without adding old releases. Later eligible releases are classified into a family/evolution, assigned a deterministic original 32x32 creature, given four legal fictional techniques and one preapproved passive, tested, proposed as a content-only PR, then published after required CI checks.

The publisher may change ONLY these data files:
- src/content/generatedModels.json
- src/game/generatedSprites.json
- data/model-observations.json

No executable code, workflows, dependencies, model inference or custom reducer effects can be generated by the publisher. Missing official evidence, ambiguous aliases, credential failures and held candidates do not delete older models.

The API list is account-specific, not a complete worldwide release directory. New-model factual capability claims remain empty if no reliable machine-readable evidence exists; game moves and power are always fictional, not real benchmarks.

## One-time production activation

1. Separately approve merging the tested branch to main and enabling daily publication. Scheduled workflows only run from the default branch. A feature-branch workflow cannot operate unattended.
2. Create a narrowly scoped GitHub App installed only on Danejw/Pokaimon with repository Contents read/write and Pull requests read/write. The App token must create the PR so GitHub actually runs CI (the built-in GITHUB_TOKEN does not trigger new PR workflows).
3. In GitHub Actions repository settings, configure variable MODEL_PUBLISHER_APP_ID and secret MODEL_PUBLISHER_APP_PRIVATE_KEY.
4. Add official model-list-only credentials to secrets OPENAI_MODEL_LIST_KEY, ANTHROPIC_MODEL_LIST_KEY, XAI_MODEL_LIST_KEY. Missing keys skip that provider without failing the others. Use minimal permissions; never place tokens in public assets.
5. Protect main and require successful verify and Generated model smoke checks. Keep squash merge enabled. Do not bypass CI or give the App administration permissions.
6. Leave repository variable MODEL_AUTOPUBLISH_ENABLED unset/false. In Actions, manually dispatch Autonomous Model Evolutions with dry_run=true. Inspect its summary and model-evolution-data artifact. First scan intentionally bootstraps the current inventory without generating old models.
7. Once the sandbox and rollback tests pass, set MODEL_AUTOPUBLISH_ENABLED=true. Future eligible releases will create data-only PRs, pass CI and merge without routine manual operations. Set this variable false to pause it.

The scheduled run is best-effort daily, not instant release detection. Missing provider data or uncertain model identity is held and retried, with reasons in the scan artifact.

## Development testing

From feat/battle-evolution after npm install:
- npm run models:validate
- npm run test -- tests/model-evolution.test.ts tests/provider-adapters.test.ts tests/evolution-passives.test.ts
- View the separate Generated model smoke CI job, which bootstraps a fictional official-source fixture in an isolated Actions runner and exercises a generated ModelDex evolution, team selection, original sprite, and battle win with Playwright. This fixture is never published to main.
- Test live discovery with node scripts/evolve-models.mjs --live in an authorized environment with read-only provider-listing keys; omit --apply for a non-writing scan.

Production rollback and a real unattended release still require live deployment setup and one genuine provider publication. A revert should be a checked content-only PR. Preserve old model identities and local save compatibility whenever possible. Never claim live zero-touch operation based on synthetic fixtures alone.
